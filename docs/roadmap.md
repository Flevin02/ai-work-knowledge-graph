# 参赛开发路线图

更新时间：2026-08-17

## 目标假设

当前按 2026 年 9 月提交作品倒排，具体提交日尚未确认。计划把 2026 年 9 月最后 7 天作为冻结和演示缓冲期；如果实际截止日更早，应优先冻结 P0/P1 功能，停止新增 P2 功能。

## 作品目标

形成一个边界清楚、主流程闭环、结果可解释、可以稳定现场演示的独立 Web 应用：

```text
导入办公资料
  → AI 提取实体、关系和证据
  → 人工审核关系
  → 交互式关系图谱
  → 健康检查和冲突提示
  → 导入新资料后增量更新
  → 导出 Markdown、JSON、图谱图片和办公摘要
```

## 功能优先级

### P0：必须完成，构成完整主线

- 独立 Next.js 项目和本地运行脚本。
- 知识空间创建、切换和删除。
- Markdown/TXT 文件导入。
- 内容指纹和重复导入识别。
- 实体提取：项目、部门、人员、任务、文档、会议、风险、决策。
- 关系提取和证据片段保存。
- 关系审核：接受、拒绝、修改。
- 关系图谱：缩放、拖拽、搜索、节点类型筛选、邻居展开。
- 节点详情：摘要、来源、证据、关系和更新时间。
- 图谱健康检查：孤立节点、待确认关系、失效来源、明显冲突。
- 虚构年会资料包和一键演示模式。

### P1：主线完整性增强，不扩张产品边界

- DOCX 和 PDF 文本导入。
- 增量导入和版本差异预览。
- 时间线视图。
- 关系按确认状态、类型和时间筛选。
- Markdown 卡片和 JSON 图谱导出。
- 当前图谱视图 PNG 导出。
- 规则检查：任务缺负责人、任务缺截止时间、项目缺来源资料。
- 失败重试和本地演示快照。

### 暂不纳入首版

- 会议纪要自动转任务。
- 周报、交接材料、通知文案和海报生成。
- 多人协作、权限和多租户。
- 复杂的关系版本回溯。
- 可配置节点类型和关系类型。

这些功能不是做得越多越好；在核心链路稳定前，全部不进入实现范围。后续若有时间，只能在不改变主线数据模型的前提下评估。

## 阶段计划

### 2026-08-17 ～ 2026-08-23：前后端基础工程和数据层

- 初始化 Next.js 前端，并基于 Firefly Boot 建立 `common + server` 两模块 Java 后端。
- 确定前后端 HTTP API 边界。
- 复用统一响应、全局异常、TraceId、Validation 和 Knife4j，清理原脚手架示例与敏感配置。
- 初始化 SQLite、Spring JDBC 和后端配置。
- 建立 source_documents、graph_nodes、graph_edges、evidences、review_actions、import_batches 表。
- 完成知识空间和本地文件目录结构。
- 完成 Markdown/TXT 导入、内容指纹和基础列表页面。
- 验收：可以导入演示资料并在数据库中看到来源记录。

### 2026-08-24 ～ 2026-08-30：AI 抽取和关系审核

- 在 Java 后端接入 Gemini API，并使用 Jackson 和 Bean Validation 校验结构化输出。
- 通过 `AiExtractionClient` 抽象供应商，Gemini 只作为首个实现。
- 实现结构化实体、关系、证据和冲突输出。
- 实现实体规范化和关系去重。
- 完成待审核关系列表。
- 验收：一批年会资料能产生可解释的关系建议，用户可以接受或拒绝。

### 2026-08-31 ～ 2026-09-06：关系图谱和节点详情

- 接入 Cytoscape.js。
- 完成聚焦图、全局图、搜索、筛选和邻居展开。
- 完成节点详情侧栏和证据定位。
- 完成图谱图片导出。
- 验收：评委可以从项目节点展开到任务和文档，并看到每条关系的来源。

### 2026-09-07 ～ 2026-09-13：维护能力和文档适配

- 完成时间线和 Markdown/JSON 导出。
- 验收：导入第二次会议纪要后能看到新增任务、状态变化和待确认关系。

### 2026-09-14 ～ 2026-09-20：完整度打磨

- 完成任务缺负责人、任务缺截止时间等规则提醒。

- 录制或整理 3～5 分钟演示流程。
- 完成作品说明、技术架构图、创新点和限制说明。

## 现场演示主线

1. 新建“2026 年公司年会”知识空间。
2. 导入第一批 7～8 份办公资料。
3. 展示 AI 识别出的实体、关系建议和证据。
4. 接受部分关系，拒绝一条错误关系。
5. 从“年会项目”节点展开部门、负责人、会议、任务和合同。
6. 打开一条关系，查看来源文档和证据片段。
7. 打开健康检查，展示孤立资料和缺少负责人提醒。
8. 导入第二次会议纪要。
9. 展示新增任务、状态变化和信息冲突。
10. 确认变更，生成项目摘要或周报。
11. 导出 Markdown、JSON 和图谱图片。

## 开发纪律

- 先保证 P0 主线闭环，再补齐 P1 的完整性能力。
- “完成度”优先于“功能数量”：不为增加演示菜单而新增旁支功能。
- 每个功能必须同时具备正常态、空态、失败态和可恢复路径。
- AI 结果必须可追溯、可审核、可拒绝，不能只展示模型生成结果。
- 不把 EIS 源码、工作文档和个人知识库接入运行时。
- 所有 AI 关系都保留证据和审核状态。
- 所有演示资料都必须是虚构或脱敏内容。
- 每完成一个阶段，至少保留一个可运行版本和一条演示路径。
- 2026-09-14 之后原则上只做稳定性、易用性、视觉和演示修复，不再扩展产品边界。
